# 我把"日更科技号"变成了一条流水线：从 37 个信息源到公众号草稿箱，全自动

> 副标题：一个本地运行的 AI 采编 Agent —— Newsmaker 开源项目实践分享

---

如果你运营过科技 / AI 方向的公众号，大概率熟悉这样一天：

早上刷几十个站点攒选题，中午让大模型写一篇初稿，下午手动改标题、找封面图、清理"AI 味"，晚上把 Markdown 一点点粘进公众号后台排版——如果还要同步一份到小黑盒，又要重新来一遍。

我也这么过了很久。后来我干脆写了个东西，把这一整套动作收进一个**本地运行的工作台**里：从信息源采集、选题、写稿、配图，到**直接调用微信官方接口把稿子送进公众号草稿箱**，全部串成一条流水线。项目开源在 GitHub，叫 **Newsmaker**。

这篇文章不卖课、不引流，就讲讲我踩过的坑和它现在能做什么。如果你也一个人运营技术内容账号，或许能少走点弯路。

## 先回答最常被问的问题：它到底是什么

一句话：**Newsmaker 是一个"本地运行的科技内容 AI 采编 Agent"**。

它不是又一个"粘贴链接帮你写文章"的在线工具，而是一整套编辑部流水线：

```
信息源 → 采集打分 → AI 选题 → 多文体写作 → 图文配齐 → 平台同步 → 发布备案
```

- **信息源**：内置 37 个科技 / AI / 游戏信息源（OpenAI、Anthropic、DeepMind、华为、智谱、DeepSeek 官方源，加上国内外科技媒体、arXiv、GitHub 热榜等），支持 RSS / 网页 / JSON / Changelog 四类接入，新增一个源只需要在 YAML 里写十行。
- **采集打分**：默认抓取最近 72 小时内容，按"官方源 + 头部公司/模型 + 发布动作 + 时效性"的规则打分，保留 Top50；中文媒体支持"只按标题过滤"，防止正文误命中。
- **AI 选题**：把当天素材按实体聚类，生成带"标题 / 角度 / 结构 / 事实清单"的选题卡，再用大模型按编辑规则打磨。
- **写作质检**：长文（公众号）、短文、小黑盒三种文体；输出会过结构化校验，不合格会自动带着"问题清单"修复重试，而不是硬塞给你一篇烂稿。
- **图文一体**：按章节规划图片槽位，候选来自官方原图、AI 生图、官方页面截图、人工上传四条路径，每张图都要经过清晰度 / 水印 / 重复审核才能入选发布位。

## 我认为它最重要的三个设计决定

**1. AI 永远不是"最后签名的人"**

所有生成结果都可编辑、可回滚：草稿每次手动保存都会留版本快照，选题卡带引用素材，配图带审核证据。AI 负责把初稿做到七八十分，剩下二十分永远是编辑的判断。这一点在内容行业不是可选项。

**2. 只走官方接口，不碰平台风控**

微信同步用的是公众号官方 `draft/add` 草稿箱接口（图片压缩、缩略图素材、整稿提交一条龙）；舆论素材走抖音开放平台授权接口采集公开评论；小黑盒目前没有公开的草稿接口，我就做成**半自动浏览器导入**：自动填标题和正文、停在草稿位等你人工审核，**绝不替你点发布**。

不做模拟登录、不抓包逆向。合规这件事，写在 README 里，也写进了代码设计里。

**3. 数据本地化，密钥不出门**

一切跑在 `127.0.0.1`。大模型走任何 OpenAI 兼容接口（DeepSeek、GLM、通义都行），密钥只存在你本机的 `.env` 里，`.env` 已被加入 `.gitignore`。采集、选题、草稿、配图、发布全部备案：JSON 实时数据 + SQLite 结构化存储 + 按日归档 + 发布指纹防重复。

## 工作台里的一天是这样过的

打开 `http://127.0.0.1:8000`，一个暗色编辑风的单页工作台，七个分页对应七个步骤：

1. **采集新闻**：勾选关键词包和信息源，点"开始采集"，评分列表刷新；
2. **生成选题**：AI 给出候选选题卡，人工可改可删；
3. **草稿与配图**：三种文体切换，图片槽位逐张审核、写图注、换候选；
4. **标题与排版**：标题多稿改写 + 平台预览 + 公众号 HTML 排版；
5. **舆论素材**（可选）：抖音评论采集 → 生成评论卡片图 → 自动插入"舆论与争议"章节；
6. **导出与同步**：微信官方草稿箱一键同步 / 小黑盒导出与半自动导入；
7. **发布备案**：打标"已发布"，指纹防重，SQLite 留档。

每一步做完，界面都会提示你下一步该干什么——状态永远可见，不会"生成完就消失了"。

## 技术栈（克制的老实组合）

后端是 Python 3.12 + Flask，前端是原生 JS 单页工作台；采集用 httpx / feedparser / BeautifulSoup；AI 调用走 OpenAI 兼容协议、配图支持阿里云 DashScope；浏览器自动化用 Playwright（官方页面截图 + 小黑盒半自动导入）；存储是 JSON + SQLite 双轨。整包依赖只在一个 `requirements.txt` 里，没有任何重型服务。

任何一个模块都能单独看懂、单独替换——这也是当初对它的要求。

## 五分钟跑起来

```bash
git clone https://github.com/RoyZ1/newsmaker.git
cd newsmaker
pip install -r requirements.txt
# 在 .env 填上任意 OpenAI 兼容模型的 KEY
python run_server.py
```

打开 `http://127.0.0.1:8000` 点"开始采集"，就是一条流水线的开始。想调文风？写作、标题、配图提示词都是可编辑的配置文件。

项目地址：**https://github.com/RoyZ1/newsmaker**
在线宣传页（GitHub Pages）：**https://royz1.github.io/newsmaker/**

> 说明：`data/` 目录下的采集产物与图片是本地运行时数据，已按设计留在仓库外；克隆后首次采集会按你的配置拉取信息源。微信同步需要公众号 AppID/AppSecret 并把服务器 IP 加入白名单，小黑盒半自动导入需要先 `python -m playwright install chromium`。

## 最后

做这个项目的初衷很简单：**让"攒素材—写初稿—排配图—过草稿"这些重复劳动尽可能自动化，把人的时间留给判断与表达。**

它现在还不是一个"全自动发稿机器人"——我也刻意没让它成为那样。它更像一个很听话的实习生：跑腿的事交给他，署名的事永远是你。
