# 参考写法提炼

这些规则来自用户提供的优质微信公众号文章，只提炼写法，不复用原句。

## 标题

- 标题要像一个判断或悬念，不要像栏目名。
- 标题还要能被搜索到。不能只写情绪和判断，必须保留一个明显关键词，比如公司名、模型名、产品名、技术名、会议名或常见场景词。
- 可以使用“新 SOTA”“开源之王”“只有它了”“然后呢？”这类强判断，但要避免夸张到失真。
- 标题里尽量保留一个具体对象：模型名、公司名、技术名、产品名。
- 如果标题有钩子但没有关键词，宁可稍微长一点，也要把关键词放进去。例如“不是入口变了”不如“阿里输入法不是入口变了”，“开始抢人的活”不如“ChatGPT Agent 开始抢人的活”。
- 不使用“正在释放哪些信号”“行业正在变化”这类模板标题。
- 标题可以采用这几种结构：
  - “具体对象 + 强判断”：例如某模型摸到第一梯队、某产品成了新入口。
  - “具体对象 + 反常识”：例如不是更大，而是更能交付。
  - “具体对象 + 结果/数字”：例如跑进秒级、覆盖百万用户、成本砍掉一半。
  - “具体对象 + 问题”：例如阿里为什么盯上输入法？
  - “旧认知被推翻”：例如 RAG 这次不靠向量了。
- 避免“新赛道”“新趋势”“行业观察”“深度解析”“几点思考”这类泛标题。

## 开头

- 第一段直接给事件，第二段给反应或冲突，第三段点出真正值得看的地方。
- 如果选题是人物故事或个人经历切入，开头先交代这个人是谁、经历了什么、这个经历为什么反常或有代表性，再引出行业问题。
- 人物开头不要只抛数字或结论；像“57 场面试才进 OpenAI”这类素材，要先让读者看见人物路径，再讨论 AI 行业门槛。
- 可以用一句口语化短句制造停顿，比如“这事有点不一样。”、“真正有意思的，不是模型本身。”。
- 不要宏大开场，不要先解释行业背景。
- 开头 3-5 段，每段可以很短，但必须一路把读者带到核心问题。

## 正文推进

- 每篇文章只围绕一个主线推进，其他事实只做证据。
- 结构要像“发现异常 -> 解释机制 -> 比较旧方案 -> 说出影响”。
- 小标题要像观点句或问题句，而不是名词目录。
- 每个技术点都要回答：它解决了什么旧问题；为什么旧办法不够；新办法真正换了什么。
- 可以先讲一个具体场景，再抽象成行业判断。
- 不要把素材平均铺开；能删掉的事实就删掉。

## 语气

- 语气可以更像认真看热闹的学生：好奇、追问、有一点判断。
- 可以使用少量口语化表达，但不要过度网感。
- 少用“因此、综上、值得注意的是、这标志着、赋能”等报告腔。
- 判断要直接，但不要装成最终结论。

## 段落和重点

- 段落要短，通常 1-3 句。
- 关键判断单独成段更有力量。
- 重要概念可以加粗；最核心的一句可以标红。
- 对技术细节的解释要具体，不要只写“效率提升”“能力增强”。

## 结尾

- 结尾不要喊口号，不要写来源。
- 最好留一个观察点：下一步看什么指标、看谁会先验证、看这个方向是否能真正落地。
- 如果素材里确实有明显的舆论倒向、正反两面或消费/玩家/用户争议，结尾可以用一个贴合现实的问题收束，引导读者参与讨论。
- 提问式结尾必须建立在前文已经讲清的矛盾上，不要为了互动硬问，不要每篇都用“你怎么看”。
